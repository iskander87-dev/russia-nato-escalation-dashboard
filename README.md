# Россия — НАТО: мониторинг эскалации

Интерактивный дашборд для ежедневного наблюдения за риском эскалации по 7-ступенчатой шкале.

## Открытие дашборда

1. Откройте опубликованную версию: [Россия — НАТО: мониторинг эскалации](https://russia-nato-escalation-monitor.ponomarev-ao.chatgpt.site).
2. В верхней части страницы проверьте дату оценки и время последнего обновления.
3. Основной индикатор показывает текущий уровень, цвет, числовую оценку, уровень уверенности и дату последнего подтвержденного факта.

## Как читать оценку

| Уровень | Цвет | Значение |
| --- | --- | --- |
| 1 | Темно-зеленый | Низкая напряженность |
| 2 | Светло-зеленый | Повышенное напряжение |
| 3 | Желтый | Гибридное давление |
| 4 | Янтарный | Пограничные инциденты |
| 5 | Оранжевый | Оперативная эскалация |
| 6 | Красно-оранжевый | Ограниченное военное столкновение |
| 7 | Красный | Широкомасштабный конфликт |

Уровень повышается только при наличии военных или оперативных признаков. Жесткая риторика сама по себе не является основанием для повышения оценки.

## Работа с дашбордом

1. Сначала посмотрите блок «Динамика и журнал»: он показывает изменение по сравнению с предыдущей оценкой и ключевые датированные события.
2. Затем сравните «Ключевые факторы повышения» и «Ключевые сдерживающие факторы». Это объясняет, почему уровень повышен или почему более высокий уровень пока не установлен.
3. Откройте «Как формируется оценка 3,6 / 7», чтобы увидеть правила работы с фактами, весом риска и источниками.
4. В разделе «Направления наблюдения» оцените ситуацию по семи областям: войска, авиация/ПВО, Беларусь/Калининград, море, гибридные операции, ядерные силы и предупреждения.
5. В «Матрице из 20 индикаторов» используйте статусы:
   - **Подтверждено** — признак подтвержден первоисточником;
   - **Частично** — есть отдельные подтверждения, но недостаточно оснований для полной фиксации признака;
   - **Не подтверждено** — для данной оценки подтверждений не найдено;
   - **Нет данных** — публичной информации недостаточно для вывода.
6. Используйте фильтры матрицы: по статусу, направлению или только по изменившимся индикаторам.
7. В каждой строке матрицы доступны дата проверки и ссылка на конкретный первоисточник. Общий журнал источников размещен в конце страницы.

## Ежедневное обновление

Мониторинг запускается ежедневно в 09:00 МСК. Он проверяет только надежные первоисточники и обновляет дашборд лишь при подтвержденном существенном изменении. При обновлении фиксируются дата, источник, пояснение, уровень уверенности и журнал событий. Если новых значимых фактов нет, оценка и страница остаются без изменений.

Проверка использует скользящее окно 96 часов и отдельно просматривает официальные порталы НАТО, правительств, министерств обороны, иностранных дел и командований вооружённых сил стран восточного и северного фланга. Для каждого инцидента раздельно оцениваются сам факт события, принадлежность аппарата или корабля, намерение и оперативное последствие. Незавершённая атрибуция не исключает подтверждённый военный инцидент из оценки; она снижает уверенность и ограничивает итоговый балл. Полные правила хранятся в `data/monitoring-policy.json`.

## Уведомления по электронной почте

Рассылка запускается GitHub Actions только при изменении файла `data/assessment.json`, который хранит текущую оценку. Адреса, добавленные кнопкой «Уведомления» на сайте, сохраняются в защищённой базе и попадают в реальную рассылку. Удаление адреса в том же браузере отключает его.

Для работы ежедневной рассылки в настройках репозитория должны быть настроены секреты:

- `RESEND_API_KEY` — ключ Resend с правом **Sending access**;
- `NOTIFICATION_RECIPIENTS` — один или несколько адресов через запятую.
- `NOTIFICATION_WEBHOOK_SECRET` — общий секрет для защищённой передачи списка подписчиков из сайта в задачу рассылки.

Опционально добавьте `RESEND_REPLY_TO`, если ответы на уведомления должны приходить на конкретный адрес. Значения секретов не публикуются.

Для первого теста в **Actions → Notify on assessment change → Run workflow** включите `send_test`. До подтверждения собственного домена Resend позволяет отправить тестовое письмо только на адрес владельца аккаунта. Ключ и адреса не попадают в исходный код, историю Git или публичный дашборд.

## Важно

Отсутствие публичных данных не означает отсутствия события. Поэтому для непроверяемых признаков используется статус «Нет данных», а не отрицательный вывод.
